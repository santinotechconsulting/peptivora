# PEPTIVORA – Production Deployment, SEO & German Regulatory Compliance Guide

## 1. Architecture Summary
PEPTIVORA is built with clean separation between public presentation, compliance enforcement, authenticated customer/KYB workflows, and staff governance:
- **Frontend**: React 19 + TypeScript + Tailwind CSS v4 with bilingual German (`/de/...`) and English (`/en/...`) clean routes, client-side head sync, and accessible breadcrumbs.
- **Server / SSR Layer (`server.ts`)**: Express backend providing:
  - Dynamic SSR HTML head injection (`<title>`, `<meta description>`, `<link rel="canonical">`, `hreflang` alternates, Open Graph, Twitter/X, Schema.org JSON-LD, and crawler semantic `<section id="ssr-crawler-context">`).
  - Dynamic `/sitemap.xml` (only published & approved products + published articles + indexable static routes) and `/robots.txt` (blocking `/api/`, `/de/compliance/`, `/de/konto/`, `/de/warenkorb/`, `/de/kasse/`).
  - Security middleware (`src/middleware/security.ts`): HTTP security headers, CSRF Origin validation on `/api/*` state changes, IP-scoped rate limiting, and plain-text XSS sanitization.
- **Database (`src/db/schema.ts` + `src/db/repository.ts`)**: 32 PostgreSQL tables managed with Drizzle ORM (`pg`), plus portable SQL + Row-Level Security policies in `supabase/migrations/0001_peptivora_schema.sql`.
- **Authentication**: Firebase Auth (`lib/firebase.ts`) with server-side ID token verification (`firebase-admin`) and 7 RBAC roles enforced in Express middleware.

## 2. Admin & Staff Operations Guide
Authorized staff access the **Compliance & Governance Console** (`/de/compliance/` or `/en/compliance/`) based on assigned RBAC role:
- **`product_manager`**: Creates drafts, edits descriptions/specifications, manages batch inventory, uploads images/documents, submits products for regulatory review, and configures product-by-product REACH/CLP safety matrices.
- **`regulatory_reviewer`**: Reviews submitted products (with mandatory **separation of duties**: reviewers cannot approve their own product submissions), verifies documents (`CoA`, `SDB/SDS`), approves/revokes KYB institution dossiers, manages the 4-pillar Pharmaceutical Gate, EU Online Pharmacy Logo settings, Business Compliance Profile, and Production Launch Checklist.
- **`content_manager`**: Edits per-page bilingual SEO metadata (`title`, `meta description`, `canonical`, `focus keyword`, `robots`), maintains Google Search Console / GA4 / GTM / Business Profile / Merchant Center integration flags, authors educational blog articles (blocked if therapeutic/medical claims appear), and updates bilingual legal documents (`Impressum`, `Datenschutz`, `AGB`, `Widerruf`, `Versand`, `Rückgabe`, `Cookie`, `Produktsicherheit`).
- **`order_manager`**: Updates fulfillment shipments and order payment settlement states.
- **`super_administrator`**: Full oversight across all panels and RBAC role assignments.

## 3. SEO Testing & Maintenance Guide
1. **Verify SSR Metadata & Crawler HTML**:
   ```bash
   curl -s http://localhost:3000/de/ | grep -E '<title>|canonical|hreflang|application/ld\+json'
   curl -s http://localhost:3000/en/catalogue/ | grep -E '<title>|canonical|hreflang'
   ```
2. **Verify XML Sitemap & Robots.txt**:
   ```bash
   curl -s http://localhost:3000/sitemap.xml
   curl -s http://localhost:3000/robots.txt
   ```
   Confirm `/de/kasse/`, `/de/konto/`, `/de/compliance/`, and `/api/` are disallowed in `robots.txt` and omitted from `sitemap.xml`.
3. **Structured Data Validation**:
   - Inspect JSON-LD blocks generated by `buildPageSeoSnapshot` in `src/core/seo/seoEngine.ts`.
   - `Product` + `Offer` schema is strictly emitted only for `published + approved` Research Division items where `pricePermitted = true` and `priceNetCents > 0`.
   - `AggregateRating` or `Review` schema is **never** fabricated.
4. **Anti-Medical Keyword Guardrail**:
   - Research-Use-Only (RUO) pages, product titles, and blog articles are screened server-side by `detectProhibitedMedicinalClaims()` against German/English therapeutic, dosage, healing, injection, or human consumption terms.
5. **Consent-Gated Google Integrations**:
   - `GA4_MEASUREMENT_ID` (`G-...`) scripts are injected client-side **only** after the user explicitly enables analytics cookies in the consent banner or Cookie Preferences page (`consentModeDefaultDenied = true`).

## 4. German Regulatory Launch Checklist (Fail-Closed)
Commercial live deployment (`productionAuthorized = true`) is rejected server-side unless ALL items are verified by a Compliance Reviewer / Super Administrator:
1. Legal entity verified (GmbH/UG, Handelsregister HRB, USt-IdNr., Geschäftsführung, street address).
2. `Impressum`, `Datenschutzerklärung`, `AGB`, `Widerrufsbelehrung`, `Versand`, `Rückgabe`, and `Produktsicherheit` reviewed by qualified German legal counsel (`legalReviewStatus = 'legal_counsel_approved'`).
3. Every Research Division product has independently verified RUO classification, non-AMG/HWG screening, and verified Safety Data Sheet (`SDB` / `SDS`).
4. Pharmaceutical Division remains **locked** (`transactionsEnabled = false`) and EU Online Pharmacy Logo remains **disabled** (`enabled = false`) unless all 4 statutory pillars (`§ 11a ApoG`, `§ 52a AMG`, `Product Authorization`, `Dispensing Workflow`) and an official `https://` authority register URL are verified.
5. Active payment & shipping providers verified without unapproved products entering checkout.

## 5. Security Checklist
- [x] Server-side RBAC + Firebase ID token verification on all `/api/compliance/*`, `/api/admin/*`, `/api/me/*`, `/api/orders/*`, `/api/documents/*` endpoints.
- [x] Rate limiting on auth/public contact/newsletter/checkout endpoints (`createRateLimiter`).
- [x] CSRF Origin guard (`csrfOriginGuard`) blocking cross-origin state-changing requests (`POST`, `PATCH`, `DELETE`).
- [x] Security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`).
- [x] Plain-text XSS sanitization (`sanitizePlainText`) and Zod schema validation on all JSON payloads.
- [x] No PAN/CVV card data ever accepted or persisted (`server.ts` + `createOrderSchema`).
- [x] GDPR Art. 15 JSON Data Export (`GET /api/me/export`) & Art. 17 Anonymization/Erasure (`POST /api/me/gdpr-erase`) preserving statutory commercial accounting records while erasing PII.

## 6. Deployment & Backup Strategy
### Build & Run
```bash
npm install
npm run lint
npm run test
npm run build
npm start
```
### Environment Configuration
Populate `.env` using `.env.example` (never commit secrets). Set `APP_URL` / `NEXT_PUBLIC_SITE_URL` to your canonical HTTPS production domain so `canonical`, `hreflang`, and `sitemap.xml` URLs resolve cleanly.

### Database Backups & Recovery
- Automated daily point-in-time Cloud SQL PostgreSQL backups in `europe-west2` (with 7–30 day retention) before schema migrations.
- Maintain immutable `audit_logs` and `approval_history` tables for German statutory HGB/AO retention requirements.

---

## 7. Known Limitations
- **Demonstration Seed Records**: Initial products, suppliers, and editorial blog articles carry demonstration notices (`isDemonstrationRecord = true`) and draft/template legal texts until replaced by verified commercial records and counsel-approved German legal copy.
- **No Unverified Claims or Integrations**: Google Search Console, GA4, GTM, Business Profile, and Merchant Center tags require valid verified organization IDs and never simulate live ranking metrics or external telemetry.
- **No Unverified Automated Pharmacy Unlocking**: Pharmaceutical dispensing remains permanently fail-closed unless manually verified and unlocked after independent statutory validation.
